OSSC Downscaler firmware
========================

An unofficial secondary firmware for the [Open Source Scan Converter](https://github.com/marqs85/ossc)
that does the opposite of the stock firmware: it takes **HD and 31kHz sources
on the VGA or component inputs** and outputs **15kHz 240p or 480i on HDMI**, for RGB CRT TVs
and 15kHz monitors (through an HDMI→VGA DAC and a VGA→SCART cable). The output
is frame locked to the input: no frame buffer, no added frame of lag.

It runs from the OSSC's secondary firmware slot ("Launch 2nd FW") and never
touches the official firmware: power cycling the OSSC always boots the
official firmware again.

Safety
------

* **15kHz output only.** Three independent layers keep the output in range:
  1. every output mode is computed for 15.6–15.9kHz (240p) or 15.7kHz (480i)
  2. anything the firmware cannot convert (no sync, unsupported input,
     out-of-range result) shows an internal 15.73kHz 240p test pattern;
  3. a hardware watchdog in the FPGA, independent of the CPU, blanks video and
     all syncs if the output line rate exceeds the threshold.
* **The official firmware is never modified.** The image only fits the
  secondary slot (flash 0x80000–0xEFFFF). This firmware's settings live in a
  single sector of its own (0xF0000) and it never reads or writes the official
  profiles, its SD card profiles or the primary image.


Requirements
------------

* OSSC board (tested on rev 1.8) with the official firmware (tested with 1.22)
  as the primary firmware
* Source on the VGA input (AV3, RGBHV) or on a component input (YPbPr)
* OSSC HDMI output → HDMI-to-VGA DAC → VGA-to-SCART (or VGA/BNC) cable → 15kHz
  RGB display. Composite sync for SCART is generated by the OSSC and sent on
  the HSYNC line ("CSync on HSYNC").


Supported inputs and outputs
----------------------------

| Input (~60Hz)       | Output | Notes |
|---------------------|--------|-------|
| 1920x1080p          | 240p / 480i | 4 input lines per output line. **Full 16:9**: the 1708x960 center window (~89% of the picture, like a TV's overscan), squeezed to 4:3. **Center 4:3**: the 1280x960 center window. Best with sources scaled x4 vertically |
| 1280x720p           | 240p / 480i | **Full 16:9** (squeezed to 4:3), **Center 4:3** (crop), **Wide (180p)** (whole 16:9 picture letterboxed: 180 lines centered, 4x4 pixel average) |
| 720x480p            | 240p / 480i | optional flicker filter in 480i |
| 640x480p            | 240p / 480i | optional flicker filter in 480i |
| 480i                | 480i, or 240p | passthrough, or each field shown as a progressive frame on the same scanlines ("480i input"). PAL (576i) is still to be investigated |

* 240p: 260–264 lines per field (15.6–15.9kHz), 480i: 525 lines.
* Every source pixel is sampled ("full resolution" sampling) and the output
  clock is generated at an exact ratio of the input clock, so horizontal
  scrolling stays smooth.
* Other native 15kHz sources are passed through unchanged; any other input
  shows the test pattern with "Unsupported".


Installation
------------

1. Copy `ossc_ds_vX.Y.bin` to a micro SD card.
2. In the **official** firmware, install it with the firmware update function
   of the settings menu. The image carries the secondary-firmware key, so it
   is written to the secondary slot only.
3. Start it with **Launch 2nd FW**. The LCD shows `DS vX.Y 15kHz` and the
   OSSC outputs the 15kHz test pattern until a supported input is found.
4. Press button 3 on the remote control (RGBHV) to switch to the correct input   

To return to the official firmware, power cycle the OSSC.


Downscaler menu
---------------

| Item | Values | |
|------|--------|---|
| Output mode | 240p, 480i | |
| CSync on HSYNC | Off (H+V), XOR, AND, Standard | composite sync type; Standard has equalizing pulses and serrated vsync. |
| 480p input | Auto, 720x480, 640x480 | 720x480 and 640x480 have the same line rate and are told apart by the hsync width; select the format manually if a source is misdetected (symptom: shimmer on horizontal motion) |
| 480i input | Passthru, 240p | 480i sources: unchanged, or both fields shown on the same scanlines as 240p (no interlacing, the picture keeps the 240p look) |
| 480i filter | Off, 1–4 | 480p / 640x480 sources with 480i output: flicker filter, each field line mixed with the lines above and below (weights a, 1-2a, a with a = level/16; 4 = 1/4, 1/2, 1/4). Higher levels: less interlace flicker, softer picture |
| HD format | Full 16:9, Center 4:3, Wide (180p) | 720p and 1080p (Wide: 720p only, 1080p uses Full 16:9) |
| Line blending | On, Off | average of the input lines that make one output line |
| Line phase | 0–3 | shifts the input line groups by whole lines, to align them with integer-scaled content |
| Width | 78%–107% | picture width, 100% = standard width (80% of the line) |
| H. position | ±40 | |
| V. position | ±12 | |
| Diagnostics | | `Rnnn`: output resyncs since boot (should stay constant while a mode runs); `Paaaa/bbbb`: measured / expected input frame period (low bits; must be equal) |

Settings are saved with **Settings opt. → Save settings** (stored in this
firmware's own sector, independent of the official profiles).


Known issues and next steps
---------------------------

* **1080p Wide** (whole 16:9 picture letterboxed, e.g. 216p) is not available
  yet; planned.
* **PAL** is still to be investigated: 576i -> 288p ("480i input") is not
  tested yet, 576p input is not supported yet (planned).


Building
--------

The firmware is built by GitHub Actions (`.github/workflows/build.yml`) with
Quartus Lite and the RISC-V toolchain; the output is `ossc_ds_vX.Y.bin`, with
the version taken from `DS_VERSION` in
`software/sys_controller/inc/firmware.h`. See [README_OSSC.md](README_OSSC.md)
for the original OSSC build instructions.
